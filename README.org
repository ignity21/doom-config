* Workflows
This section is the day-to-day memory for the configuration currently loaded
from =config.d.new/=.

** Migration memory
- The startup currently loads the legacy =config.d/= first and then
  =config.d.new/=.  A migrated behavior must have one source only; remove its
  old implementation when its replacement is verified.
- =config.d.new/ai.el= owns gptel provider and credential configuration.
  =modules/cc/ai= owns the separate =ai-code= package and its direct
  ~C-c a~ entry point.  Aidermacs is retired and no longer declared.

** Search, inspect, and navigate code
1. Use ~C-s~ for the current buffer, or ~C-c s d~ for a ripgrep search.
2. Use ~M-.~ to jump to a definition and ~M-,~ to return.
3. Use ~C-c . f~ for symbols in the current file; in an LSP project,
   ~C-c . p~ searches project symbols and ~C-c . r/i/t/d~ finds references,
   implementations, type definitions, and documentation.
4. Use ~C-c s i/I~ for the current buffer's imenu or a multi-buffer imenu.

** Edit, evaluate, and run code
- ~C-c c f~ formats the current region or buffer; LSP formatting is also
  enabled on save.
- The =F5= prefix is for running and evaluation: =F5 b= evaluates a buffer or
  region, =F5 e= evaluates a line or region, =F5 s= sends a region to a REPL,
  and =F5 r= opens a REPL.  =F5 q= runs Quickrun; press =F5 F5= for Quickrun's
  shell runner.
- In Emacs Lisp buffers, use ~C-c c c~ to byte-compile, ~C-c c d~ to
  disassemble, and ~C-c c ]~ to check parentheses.

** Review diagnostics and fix code
- In a Flycheck-enabled buffer, use ~C-c 1 n/p/a~ for next, previous, and
  first error; ~C-c 1 l~ opens the error list and ~C-c 1 s~ verifies checker
  setup.
- Use ~C-c c a~ for code actions and ~C-c c r~ to rename an LSP symbol.
  ~C-c c m i~ toggles LSP inlay hints; ~C-c c s r~ restarts the LSP workspace.
- Python buffers use =basedpyright= and =ruff= by default.  Set
  ~cc/python-use-ty-p~ to use =ty-ls= plus =ruff= globally, or add the
  documented ~lsp-enabled-clients~ value to a project's =.dir-locals.el=.
- Use ~C-c c d~ in a Python buffer to disassemble the current region, or the
  whole buffer when no region is active.

** Complete and write
- In Vertico, ~C-o~ previews the candidate, ~C-l~ edits a directory path, and
  ~C-M-n/p~ moves between groups.
- In Corfu, ~C-c C-l~ moves completion to the minibuffer, ~C-SPC~ inserts a
  separator, ~<tab>~ quick-completes, and ~C-h~ toggles popup information.
- Minuet is the default inline completion provider (=use-minuet-p= in
  =packages.el=).  It is active in programming, YAML, and configuration
  buffers, and only requests a suggestion after buffer changes.  When a
  suggestion is visible: ~M-RET~ or ~<right>~ accepts it, ~M-l~ accepts one
  line, ~M-i~ requests one, ~M-n/p~ cycles, and ~C-g~ dismisses it.
- Copilot is the alternative provider.  Switch the package choice in
  =packages.el=, run ~doom sync~, and restart Emacs; then ~C-c t o~ toggles
  Copilot and ~C-c t n~ toggles NES mode.

** Ask an LLM with gptel
1. Put only the provider keys you use in the ignored =custom-vars.el=; copy
   =custom-vars.example.el= as the starting point.  A backend is registered
   only when its key is non-empty; set ~cc/gptel-default-backend~ to an
   available provider.
2. Open a chat with ~C-c o l l~.  In a source or text buffer, select text when
   appropriate and use ~C-c o l s~ to send it.
3. Use ~C-c o l a/f~ to add text or a file to the chat context, ~C-c o l r~ to
   rewrite, and ~C-c o l e~ for a quick explanation.  In Org, ~C-c o l o/O~
   limits context to the heading or sets gptel Org properties.

** Files, projects, and tools
- ~C-c f r~ opens recent files; ~C-c f p/P~ finds or browses this Doom
  configuration; ~C-c f e/E~ does the same for Doom itself.  ~C-c f y~ copies
  the current file path.
- ~C-c o t~ opens Ghostel, ~C-c o d~ opens Docker when enabled, and ~C-c o c~
  opens Calendar.
- ~F12~ toggles the configured light/dark ef themes; ~S-F12~ picks a random
  light theme.

** Modern Emacs Lisp
*** Variables
- Use ~defcustom~ for user-facing options.  Give it a docstring, ~:type~, and
  an appropriate customization group.
- Set Customize options with ~setopt~.  It runs the option's setter and checks
  the value.  Use ~setq~ for ordinary state, ~setq-local~ for buffer-local
  state, and ~defvar-local~ for buffer-local variables.
- Use ~defconst~ for configuration constants such as shared key-prefix strings.

*** Keymaps and bindings
- Create a named keymap with ~defvar-keymap~ (or ~define-keymap~ for an
  expression).  Do not introduce new uses of ~make-sparse-keymap~ plus ~setq~.
- Bind native global, local, and explicit maps with ~keymap-global-set~,
  ~keymap-local-set~, and ~keymap-set~.  Do not introduce new uses of
  ~define-key~, ~global-set-key~, or ~local-set-key~.
- Continue to use Doom's ~map!~ when its descriptions, conditional bindings,
  mode-map targeting, or prefix DSL make the declaration clearer.  Give custom
  prefixes a which-key description.

*** Hooks, advice, and mutable data
- Prefer named functions registered with ~add-hook~.  Use ~add-hook!~ only when
  Doom's multi-mode or inline-function syntax is materially clearer; avoid
  anonymous functions in global hooks.
- Prefer hooks, variables, or key remapping over advice.  When advice is
  necessary, use named ~define-advice~ or ~advice-add~ and document why it is
  needed; do not use obsolete ~defadvice~.
- Use ~setf~ for generalized places such as ~alist-get~ and ~plist-get~.  When
  using ~plist-put~, always keep its returned plist so a newly added property
  cannot be lost.
