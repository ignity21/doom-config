* Workflows
This section is the day-to-day memory for the configuration currently loaded
from =config.d.new/=.

** Search, inspect, and navigate code
1. Use ~C-s~ for the current buffer, or ~C-c s d~ for a ripgrep search.
2. Use ~M-.~ to jump to a definition and ~M-,~ to return.
3. Use ~C-c . f~ for symbols in the current file; in an LSP project,
   ~C-c . p~ searches project symbols and ~C-c . r/i/t/d~ finds references,
   implementations, type definitions, and documentation.
4. Use ~C-c s i/I~ for the current buffer's imenu or a multi-buffer imenu.

** Ansible
The =:tools ansible= module activates its project assistance in YAML projects
that contain markers such as =roles/=, =tasks/main.yml=, =ansible.cfg=, or
=galaxy.yml=.  Jinja templates ending in =.j2= use Jinja2 mode.  Ansible must
be installed locally; the current installation is Ansible 2.21.2.

In an Ansible buffer, use Doom's local leader (normally ~SPC m~ in Evil) then:
- ~h~ to look up an Ansible module with =ansible-doc=;
- ~d~ to decrypt a Vault buffer;
- ~e~ to encrypt a Vault buffer.

For day-to-day work, edit a role's =tasks/main.yml=, look up unfamiliar module
arguments with ~SPC m h~, then run =ansible-lint= or
=ansible-playbook --check= from the project's terminal.  Vault password-file
settings should be project-local (for example via =.dir-locals.el=), never
committed with a password.

** Project environments with direnv
The =:tools direnv= module imports the authorized project's =.envrc= into the
Emacs buffers that belong to it.  This keeps per-project executables, virtual
environments, and non-secret configuration available to terminals, tools, and
language servers without modifying the global Emacs environment.

Create =.envrc= at the project root, review it as executable shell code, then
run =direnv allow=.  Repeat =direnv allow= after changing it; use =direnv deny=
to revoke authorization.  Do not commit secrets in =.envrc=; instead keep them
in an ignored file such as =.env.local= and load it only when needed.

For a Python project managed by =uv=, first run =uv sync= to create =.venv=,
then a minimal =.envrc= can be:
#+begin_src sh
watch_file pyproject.toml uv.lock
source .venv/bin/activate
dotenv_if_exists .env.local
#+end_src

When a file is visited, Emacs applies that environment before mode hooks run.
Changing or re-authorizing the environment refreshes the affected buffers and
restarts their associated LSP server automatically.

** Project style with EditorConfig
The =:tools editorconfig= module applies the nearest project =.editorconfig=
when a file is visited.  Project rules take precedence over this configuration's
language defaults, so use them for shared indentation, whitespace, and newline
conventions rather than adding one-off Emacs settings.

Use ~C-c p e~ to open the EditorConfig file that applies to the current buffer.
Place a =root = true= file at a repository root when its rules must not inherit
from parent directories.  The native =editorconfig= executable is installed and
used when available; Emacs has an elisp fallback for projects and machines
without it.

** Look up code and documentation
Use ~M-.~ to find a definition and ~M-,~ to return.  Under ~C-c .~, use ~r~,
~i~, ~t~, and ~d~ for references, implementations, type definitions, and
documentation.  These commands prefer language-server and xref results, then
fall back to project search when necessary.

Use ~C-c l f~ to open a file named at point, ~C-c l o~ for an online search,
~C-c l d~ for an online dictionary definition, and ~C-c l D~ for synonyms.
The configured =+dictionary= flag uses online services; offline wordnet and
Dash docsets are intentionally not enabled.

** Git with Magit
Start with ~M-x magit-status~ (or Doom's ~SPC g g~ when using its Evil leader).
In the status buffer, stage or unstage the item at point with ~s~ or ~u~, inspect
changes with ~d~, create or switch branches with ~b~, and browse history with
~l~.  Use the push and pull dispatch menus (~P~ and ~F~) rather than memorizing
remote commands; type ~?~ in any Magit buffer to see its context-specific keys.

After staging a coherent change, start a commit with ~c c~.  In the commit
message buffer, ~M-x gptel-magit-generate-message~ can draft the configured
Conventional Commit subject; review it, edit it as needed, then finish with
~C-c C-c~.  Magit executes real Git operations, so inspect the target branch,
remote, and staged diff before pushing or committing.

** Docker
The =:tools docker= module provides the Docker management UI at ~C-c o d~,
Docker container TRAMP paths such as =/docker:container:/path/to/file=, and
=dockfmt= formatting for Dockerfiles.  Its =+lsp= and =+tree-sitter= flags are
both enabled: LSP supplies Dockerfile semantic assistance, while tree-sitter
provides local syntax parsing and structural editing.  They are complementary.

** Edit, evaluate, and run code
- ~C-c c f~ formats the current region or buffer.  On save, Doom's formatter
  runs once and uses LSP when appropriate.
- The =F5= prefix is for running and evaluation: =F5 b= evaluates a buffer or
  region, =F5 e= evaluates a line or region, =F5 s= sends a region to a REPL,
  and =F5 r= opens a REPL.  =F5 q= runs Quickrun; press =F5 F5= for Quickrun's
  shell runner.
- In Emacs Lisp buffers, use ~C-c c c~ to byte-compile, ~C-c c d~ to
  disassemble, and ~C-c c ]~ to check parentheses.

** Review diagnostics and fix code
- In a Flycheck-enabled buffer, use ~C-c 1 n/p/a~ for next, previous, and
  first error; ~C-c 1 l~ opens the error list and ~C-c 1 s~ verifies checker
  setup.
- Use ~C-c c a~ for code actions and ~C-c c r~ to rename an LSP symbol.
  ~C-c c m i~ toggles LSP inlay hints; ~C-c c s r~ restarts the LSP workspace.
- Python buffers use =basedpyright= and =ruff= by default.  Set
  ~cc/python-use-ty-p~ to use =ty-ls= plus =ruff= globally, or add the
  documented ~lsp-enabled-clients~ value to a project's =.dir-locals.el=.
- Use ~C-c c d~ in a Python buffer to disassemble the current region, or the
  whole buffer when no region is active.
- YAML files use ~yaml-ts-mode~ with a two-space indentation engine supplied
  by =yaml-mode=; customize ~cc/yaml-indent-offset~ to change the width.

** Complete and write
- In Vertico, ~C-o~ previews the candidate, ~C-l~ edits a directory path, and
  ~C-M-n/p~ moves between groups.
- In Corfu, ~C-c C-l~ moves completion to the minibuffer, ~C-SPC~ inserts a
  separator, ~<tab>~ quick-completes, and ~C-h~ toggles popup information.
- Minuet is the default inline completion provider (the =+minuet= flag on the
  =:cc completion= module in =init.el=).  It is active in programming, YAML,
  and configuration buffers, and only requests a suggestion after buffer
  changes.  When a suggestion is visible: ~M-RET~ or ~<right>~ accepts it,
  ~M-l~ accepts one line, ~M-i~ requests one, ~M-n/p~ cycles, and ~C-g~
  dismisses it.
- Copilot is the alternative provider.  Switch the module flag to =+copilot=
  in =init.el=, run ~doom sync~, and restart Emacs; then ~C-c t o~ toggles
  Copilot and ~C-c t n~ toggles NES mode.

** Ask an LLM with gptel
1. Put only the provider keys you use in the ignored =custom-vars.el=; copy
   =custom-vars.example.el= as the starting point.  A backend is registered
   only when its key is non-empty.  If the configured default is unavailable,
   gptel selects a deterministic available fallback; if none exists, Emacs
   shows a warning instead of opening a broken chat buffer.
2. Open a chat with ~C-c g c~.  In a source or text buffer, select text when
   appropriate and use ~C-c g s~ to send it.
3. Use ~C-c g a/f~ to add text or a file to the chat context, ~C-c g r~ to
   rewrite, and ~C-c g e~ for a quick explanation.  In Org, ~C-c g o/O~
   limits context to the heading or sets gptel Org properties.
4. In a Magit commit-message buffer, run ~M-x gptel-magit-generate-message~.
   Generated Conventional Commit subjects target 60 characters, use the Git
   summary limit (currently 72) as their hard cap, and remain on one line; use
   the optional body for details.

** Files, projects, and tools
- ~C-c f r~ opens recent files; ~C-c f p/P~ finds or browses this Doom
  configuration; ~C-c f e/E~ does the same for Doom itself.  ~C-c f y~ copies
  the current file path.
- ~C-c o t~ opens Ghostel, ~C-c o d~ opens Docker when enabled, and ~C-c o c~
  opens Calendar.
- ~F12~ toggles the configured light/dark ef themes; ~S-F12~ picks a random
  light theme.
