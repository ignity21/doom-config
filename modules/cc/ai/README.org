* gptel backends

Built-in backends (OpenAI / DeepSeek / Anthropic / Gemini) are registered
from their own ~cc/*-api-key~ options.  Two more are gated by a boolean:

- ~cc/gptel-enable-copilot~ -- GitHub Copilot (~Copilot~).
- ~cc/gptel-enable-openai-sub~ -- ChatGPT Plus/Pro subscription via OAuth
  (~openai-sub~).  After enabling, run ~M-x gptel-openai-oauth-login~ once
  to authenticate.

~gptel-magit~ (commit messages) can run on a different backend/model than
the chat default: set ~cc/gptel-magit-backend~ (a ~cc/gptel-backends~ key)
and ~cc/gptel-magit-model~.  Both nil = follow the active backend.  Note
~gptel-magit~ sends *non-streaming* requests, so it cannot use
~openai-sub~ (the ChatGPT OAuth endpoint is stream-only and returns
HTTP 400) -- pick ~deepseek~ / ~copilot~ / ~anthropic~ / ~openai~.

** Custom OpenAI-compatible vendors

Any other OpenAI-compatible vendor (Groq, OpenRouter, SiliconFlow,
OpenWebUI, a local vLLM, ...) goes in ~cc/gptel-openai-compatible-vendors~
in ~custom-vars.el~ as a list of plists.  It is *pure data*: the actual
~gptel-make-openai~ call is deferred to this module's ~after! gptel~
block, so the setting stays harmless when the ~:cc ai~ module is disabled.

#+begin_src elisp
(setopt
  cc/gptel-openai-compatible-vendors
  '((:id groq
     :name "Groq"
     :host "api.groq.com"
     :endpoint "/openai/v1/chat/completions"
     :key "gsk_..."
     :models (llama-3.3-70b-versatile
              (moonshotai/kimi-k2-instruct :capabilities (tool))))))
#+end_src

Plist keys:

| key               | req? | notes                                             |
|-------------------+------+---------------------------------------------------|
| ~:id~             | no   | registry key; also a valid ~cc/gptel-default-backend~ value. Defaults to a slug of ~:name~. |
| ~:name~           | yes  | shown in gptel; must differ from built-in names.  |
| ~:host~           | yes  | e.g. ~api.groq.com~                               |
| ~:key~            | yes  | API key                                           |
| ~:models~         | yes  | symbols or ~(symbol . plist)~ specs; a missing list skips the vendor with a warning. |
| ~:endpoint~       | no   | default ~/v1/chat/completions~                    |
| ~:protocol~       | no   | default ~https~                                   |
| ~:stream~         | no   | default ~t~                                       |
| ~:header~ / ~:request-params~ / ~:curl-args~ | no | passed through to ~gptel-make-openai~ |

Make a custom vendor the default backend:

#+begin_src elisp
(setopt cc/gptel-default-backend 'groq)
#+end_src

For models that support OpenAI-compatible tool calling, use a full model
specification with ~:capabilities (tool)~.  The file tools in ~+tools.el~ are
enabled by default.  They can list and read files, and can write or perform an
exact replacement after confirmation.  Access is limited to the current
project unless ~cc/gptel-file-tool-roots~ names explicit allowed directories.

Find a vendor's model ids:

#+begin_src bash
curl -s https://<host>/v1/models -H "Authorization: Bearer $KEY" | jq '.data[].id'
#+end_src

** Fetching model lists automatically

gptel's built-in ~:models~ lists are static and lag the providers.
[[https://github.com/cat-emacs/gptel-model-updater][gptel-model-updater]]
(pinned) is loaded on first use of one of its commands:

- ~M-x gptel-model-updater-update-all~ -- refresh every registered backend
- ~M-x gptel-model-updater-update-backend~ -- refresh one
- ~M-x gptel-model-updater-transient~ -- menu (also under ~-u~ in ~gptel-menu~)

Fetched ids are merged into the live backend (existing ~:models~ and
their metadata win) and matched against models.dev for cost / context /
capabilities.  Results are *in memory only* -- re-run after each restart.

Only backends the updater can actually reach are registered
(`cc/gptel--model-updater-can-fetch-p'): it builds the models URL by
trimming ~chat/completions~ off the endpoint, so it excludes

- *OpenAI* and *openai-sub* -- Responses-API endpoint, no ~/models~ path;
- *Anthropic* -- not OpenAI-compatible.

gptel's static lists for those three are well maintained (and this module
unpins gptel in ~packages.el~ to track upstream, so they stay current),
so nothing is lost.  *Gemini* is registered but its fetch needs direct
network access
(it times out otherwise -- ignore it, or drop ~cc/gptel-backend--gemini~
from ~gptel-model-updater-backends~).  A custom vendor only works if its
~:protocol~/~:endpoint~ point at a real OpenAI-style ~/v1/models~.

* Aider Models
- ~aider --list-models [copilot]~
- check the output of the following command to find the model id for copilot:
#+begin_src bash
curl -s https://api.githubcopilot.com/models \
  -H "Authorization: Bearer $(cat ~/.config/litellm/github_copilot/access-token)" \
  | jq '.data[] | {id: .id, type: .capabilities.type}'
#+end_src
